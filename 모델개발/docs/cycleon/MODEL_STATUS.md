# 모델 진행상황과 입출력

> Draft v0.1 · 문서 기준 2026-10-29 KST. 전체 개발 미완료. 모델 성능 목표와 API 연동 가능 상태를 구분한다.

## 문제와 출력 정의

기준 정각 t에 알고 있던 정보로 t+1/t+2/t+3시간 **정각**의 대여소 수량이 0대인지 예측한다. 각 대여소·h의 출력은 확률, 저장 임계값의 위험 판정, 사용한 모델 ID/입력 그룹 또는 예측 보류 사유다.

최신 재고는 사용자 조회 시각의 수량 정보이며 정각 모델 입력과 별도로 전달한다. 현재 0대도 예측할 수 있다. 추천은 현재 양수·신선한 재고와 유효 확률이 있는 후보로 제한한다. 위험 확률과 거리의 균형은 별도 정책 선택으로 결정한다.

## 준비 상태

| 항목 | 확인 결과 |
| --- | --- |
| 2026-10-29 13:41 저장 집계 | **8/64 설정, 실제 적합 16회** |
| 완료한 설정 구성 | T LightGBM h1/h2/h3, C LightGBM h1/h2/h3·공통 모델, S LightGBM h1 |
| 제공 중인 개발 번들 | development_TC_20261027_v2. T/C 개별 간격 모델을 API에 연결한 이력 있음 |
| 실모델 재추론 | T/C 각 h1/h2/h3의 저장 표본 256행 재추론 일치 확인. 성능 재평가와 별개 |
| 현재 소스 입력 | T/C/S 준비. W/F/E는 기상 출처 검수·결합 gate 미통과 |
| 최종 모델·추천 정책 | 미선정·미고정 |
| 2025년 하반기 독립평가 | 미실시 |
| 24시간 수집·장애 복구·p95 | 최종 검증 미완료 |

설정 완료 수와 적합 횟수는 다르다. 내부 조기종료와 전체 재적합을 별도 적합으로 집계한다. 위 수치는 문서 작성용 스냅샷이며 실시간 진행률이 아니다. 현재 포트와 모델 상태는 실서버의 `/v1/status` 및 담당자 확인이 필요하다.

## 학습 입력과 실제 API 입력

프론트/앱 백엔드는 station_ids와 horizons_hours 또는 위치·horizon·반경을 보낸다. 원시 특징 벡터·예보를 사용자 요청 body에 넣지 않는다. AI 내부가 저장 자료를 조회해 학습과 같은 특징 코드를 실행한다.

| 묶음 | 열 수 | 구성 | 현황 |
| --- | --- | --- | --- |
| C | 8 | 대여소 코드·현재 재고·달력·h 등 짧은 이력 | 개발 경로 |
| T | 22 | C + 1/2/3/24/168h lag·증감·과거 통계 | 개발 경로, 실제 168h 이력 조건 유지 |
| S | 40 | T + 500m·최근접 5곳의 재고·변화 | 데이터 준비, 일부 학습 |
| W | 46 | S + 기준 전 현재 기상 실황·나이 | 검수 대기 |
| F | 46 | S + 기준 전 발표한 목표 정각 예보·나이 | 검수 대기 |
| E | 57 | S + 실황·예보 + 검수를 통과한 추가 환경 입력 | 검수 대기, 과거 대기질을 현재 값으로 소급하지 않음 |

열 정의는 `cycleon/features.py:FEATURE_COLUMNS`가 기준이다. T 및 관련 장기이력 경로는 t-168h 실제 관측, 기준 재고 및 최근 24시간 최소 12개 유효 관측을 요구한다. 조건을 충족하지 못하면 다음 검증된 C 경로로 전환하거나 null을 반환한다. 신규 ID·좌표·기상 누락은 무조건 수량 0으로 대치하지 않는다.

## 번들과 모델 교체

모델 파일은 Git으로 배포하지 않는다. 연구실 경로의 개발 번들에는 manifest와 h별 LightGBM 파일이 있으며 시작 시 로드한다. manifest에는 id/stage, 대여소 코드북, 경로별 group/columns, 모델 종류·파일·해시·적용 horizon, h별 보정값·임계값, recommendation_policy가 포함된다.

팀 서비스는 model_id를 고정하지 말고 응답에서 읽는다. 최종 선정 후 API 의미·스키마를 유지하면서 모델 담당자가 번들을 교체하고 재현성·추론을 확인한다. 토큰·동작 주소·모델 해시 인계와 실행 승인은 Git 초안 공유와 구분한다. 다운로드 가능한 최종 모델 릴리스는 아직 없다.

현재 T/C 번들의 C 모델 ID는 `cold_C_default_lightgbm_individual`, T는 `basic_T_default_lightgbm_individual`이다. manifest stage는 `development_only_incomplete_64_configurations_no_independent_final_test`, recommendation_policy는 null이다.

## 평가와 남은 모델 작업

64개 설정 범위를 유지한다. LightGBM·CatBoost·50:50 확률 결합, 공통 모델과 h별 모델, 짧은 이력 경로를 비교한다. 2022~2024 학습, 내부 조기 종료 후 전체 재적합, 2025년 1~2월 보정·3~4월 선택·5~6월 확인, 모델/정책 고정 후 7~12월 독립평가를 계획한다.

주지표는 h별 F1과 단순 평균, 7일 블록 신뢰구간 및 신규 고갈 전환 재현율 비악화다. 오경보·누락·보정·입력 누락률·계절 편차도 보고한다. 추천은 전체 요청을 분모로 유효율·보류율·추가 직선거리(평균 100m 목표)를 평가한다. 평균 F1 +5%p, 조회 p95 2초는 목표이며 완료 수치가 아니다.

기존 v4 M2 F1 73.831%와 후속 v7 최고 74.255%는 **1시간·기존 상반기 개발 비교**다. 새 1~3시간 번들 성능이나 독립평가 성과로 사용하지 않는다. v7 최고 후보의 전환 재현율 악화도 별도 기록한다. 누수 진단 결과는 성과에 포함하지 않는다.

## 알려진 제약

- 과거 기상 파일과 API 표본에서 기온/습도 불일치가 남아 있어 W/F/E를 막았다. 시간 매핑은 공식 기준과 대조했다.
- 과거 재고 원본에는 실제 수신 시각이 없어 기록 정각을 이용한 조건부 재현이며, 과거 좌표 snapshot의 적용 시점 한계가 있다.
- CatBoost 전체 재적합에 메모리 제약이 있고 범주형 경로 동등성 확인이 남았다. 다른 연구 프로세스를 종료하거나 행·설정을 줄이지 않는다.
- 현재 개발 모델의 응답 확인과 공유 실서버의 지속 가동은 별개다. 10/29 13:47에는 8001/8002 listener가 없었다.

제안서 방향의 모델·특징·평가를 모델 담당이 계속 개발하고, 백엔드/프론트는 이 계약의 모의 환경으로 병행 개발한다.
