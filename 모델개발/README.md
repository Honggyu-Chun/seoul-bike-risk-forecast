# 따릉이, 어디로? — 시민용 예측·비교 연구 데모 2.0

> 이 문서는 기존 1시간 예측 시제품과 과거 연구의 기록으로 보존한다. 최신 1·2·3시간 이용 시각 선택 프로젝트의 목적·개발 범위·협업 절차는 [저장소 루트 README](../README.md)를 기준으로 확인한다. 아래 일부 산출물 링크는 Git에서 제외한 로컬 자료를 전제로 한다.

따릉이를 빌리려는 시민이 **현재 수량·다음 시간대의 0대 위험·거리**를 비교하는 시제품입니다. 서울시 실제 원본을 검수하고 Baseline과 제안 모델을 학습·시험했으며, 과거 시험 재생과 공식 실시간 샘플의 기본 모형 실행을 구현했습니다.

**후속 새 시험:** 전체 F1은 72.959% → 74.070% (+1.111%p), 거리 기준 대비 유효추천율은 +4.022%p였습니다. 초기 두 +5%p 목표는 미달이며, 새 보고서에서 실제 성능과 사용 범위를 구분합니다.

**기존 3월 실험의 결론:** 데모는 작동하지만 주변 정보를 더한 M1의 우수성과 실제 시민의 헛걸음 감소는 입증하지 못했습니다. 전체 F1의 작은 상승과 대여자에게 중요한 전환 탐지의 부족을 함께 공개합니다. 후속 M2 연구는 별도의 새 기간에서 비교합니다. 기존 행사·대여 건수 기획과 소규모 예비실험은 이전 범위로, 아래 실제 결과와 섞지 않습니다.

## 데모 실행

Python 3.12·uv·고정 의존성 `uv.lock`을 사용합니다. 현재 클라우드에는 모델과 시험 예측 산출물이 준비되어 있습니다. 다른 PC에서는 실행 패키지 ZIP을 풀거나 아래 원본 확보·학습 절차를 실행하세요. 모델·Parquet는 Git에서 제외되어 Git clone만으로 자동 확보되지는 않습니다.

```bash
cd /workspace/P_Project
export UV_CACHE_DIR=/workspace/.cache/uv
export XDG_CACHE_HOME=/workspace/.cache
uv sync --frozen
bash scripts/run_demo.sh
```

서버 포트는 8000입니다(`BIKE_DEMO_PORT`로 변경). 실행 환경의 브라우저 연결 방식으로 엽니다. 내부 준비 확인: `GET /api/health`, `GET /api/overview`. 외부 공개 사이트를 배포한 상태는 아닙니다. 새 작업에서 서버 프로세스가 유지된다고 가정하지 마세요.

과거 화면에서 기준 시각·위치·500m 범위를 선택하고 정답 표시·도움/불리 사례를 확인합니다. 위치도는 실제 좌표를 그린 것으로 도로·보행 경로 안내가 아닙니다.

### 실시간 예측은 어디까지 가능한가

- 공식 공개 `sample/json/bikeList/1/5`의 **5곳** 현재 수량을 받아 별도 모형 **B1S**를 실행했습니다. 증빙: `artifacts/evaluation/live_demo_check.json`.
- 현재 수량 `parkingBikeTotCnt`와 설치 거치대 수 `rackTotCnt`를 구분합니다. 대여소별 원천 관측시각이 없어 서버 수신시각을 따로 표시합니다. 30초 캐시로 중복 요청을 줄입니다.
- 본인 발급키를 서버 환경변수 `SEOUL_API_KEY`로 설정하면 전체 페이지 조회 코드를 사용할 수 있습니다. **발급키 전체 조회는 미검증**입니다. 문서상 한 호출 최대 1,000건이며 갱신 간격·장기 호출 한도는 별도 확인 사항입니다. 키를 채팅·프런트 코드·저장소에 남기지 마세요.
- 전체 이웃과 과거 이력이 없어 **실시간 M1 결과라고 표시하지 않습니다.** B1S도 2025년 1분기 모형에 2026년 현재 입력을 넣은 실행 시연입니다. 현재 정확도·5~10분 뒤 정확도는 미검증입니다.
- 한 번의 호출은 1·24·168시간 전 이력을 만들지 않습니다. 전체 수량의 누적 수집, 시간·번호 연결, 새 정답과 기간별 검증이 필요합니다.
- 아래 수집 도구는 지정 횟수만 실행합니다. 24시간 수집 서버는 시작하지 않았습니다.

```bash
uv run --frozen python scripts/collect_live.py --iterations 1
```

## Baseline·제안 모델과 실제 결과

- **B0:** 현재 0대 여부 유지. 학습 없는 기준.
- **B1:** 자기 정보16개 특징의 LightGBM. 현재 수량·시간·요일·1/2/24/168시간 전 수량·3/24시간 평균과 관측수·변화량.
- **M1:** 같은 LightGBM에 500m 이웃 정보11개 추가, 총27개. 이웃 평균·표준편차·최소·0대/저수량 비율·관측수·이웃수·커버리지·변화·자기와 차이.
- **B1S:** 현재 수량 중심6개 특징의 별도 실시간 참고 모형. 주 Baseline B1과 구분.

정답 시각 기준 학습1~2월 **3,716,886건**, 검증3/1~14 **916,608건**, 시험3/15~31 **1,112,738건**입니다. 0대를 위험인 양성으로 둡니다. B1/M1은 후보2개·최대240회·조기 종료30회로 같은 조정 예산을 썼습니다. 학습률.05, seed20261019,4스레드, 경고 기준은 검증 F1로 .05~.95에서 고른 **.35**입니다. 선택된 후보는 leaves63/minleaf500, B1 240회·M1 164회입니다. 시험 전에 선택 결과·해시를 저장했습니다.

|방법|F1|정밀도|재현율|놓친 0대|
|---|---:|---:|---:|---:|
|B0|75.400%|75.365%|75.436%|27,618|
|B1|75.741%|75.071%|76.423%|26,508|
|M1|75.766%|74.724%|76.837%|26,043|

M1−B1 F1은 **+0.0245%p**, 놓침465건 감소·오경보689건 증가입니다. 하루 전체를 묶어 1,000번 짝지어 재표집한 탐색적95% 차이 범위는 **−0.0447~+0.1038%p**로 0을 포함합니다. 확실한 우수성은 미입증입니다.

중요한 약점은 **현재 양수 대여소의 다음 0대 전환 재현율이 M1 9.396%**이고, 해당 F1도 B1 15.774% → M1 15.462%로 떨어졌다는 점입니다. 전체 F1은 실제 대여 성공률이 아닙니다. 이후 연구는 현재 양수·저수량 전환과 새로운 기간·짧은 간격 자료에 집중해야 합니다.

### 추천 결과

학습 좌표 근처 고정 가상 출발지120개, 평일7/8/18/19시,500m 이내 현재 양수·다음 정답 후보로 **5,224개 공통 요청**을 비교했습니다(5,280개 중 후보 없는56개 공통 제외). 실제 이용자의 출발지 분포가 아니며 거리 기준에 유리할 수 있습니다.

|방식|유효 추천/전체|유효추천율|보류율|짝지은 추가 직선거리|
|---|---:|---:|---:|---:|
|R0 현재 양수·가까운 곳|4,972/5,224|95.176%|0.000%|0.00m|
|R1 B1 위험 제외·가까운 곳|4,987/5,224|95.463%|0.211%|2.40m|

유효추천율은 다음 기록에1대 이상인 곳을 추천한 요청/전체 요청으로 보류도 분모에 남깁니다. R2는 R0보다10건 더 유효하지만 R1보다5건 적었습니다. 실제 대여·헛걸음·보행 경로 효과는 미검증입니다.

초기 잠정 목표 F1+5%p·유효추천율+5%p는 **미달**입니다. 기준95.176%에서 +5%p는100% 상한을 넘어 목표 자체에 문제가 있었습니다. 학교가 정한 합격선이 아닙니다. 소급 달성으로 바꾸지 않고 새 목표는 새로운 검증자료·미사용 시험으로 설계해야 합니다.
