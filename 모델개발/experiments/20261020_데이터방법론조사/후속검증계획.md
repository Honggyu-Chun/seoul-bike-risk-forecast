# 후속 모델 실험 설계

상태: 조사 단계의 실행 전 설계안으로 작성한다. 사용자 확인에 따라 이번 작업에서는 모델 구현·학습·새 성능 평가를 수행하지 않는다. 기존 `config/improvement_v3.json`과 고정 결과를 수정하지 않는다.

## 1. 검증할 과제를 고정한다

주목적은 대여소 s의 입력 시각 t에서 **정확히 다음 1시간 격자 관측 수량이 0인지** 예측하는 것으로 유지한다. 양성은 `Q(s,t+1)=0`으로 정의한다. 현재 관측이 있고 다음 격자에 유효한 관측이 있는 경우만 평가한다.

- 1시간 내내 비어 있음, 실제 대여 실패, 고장 여부와 5~10분 뒤 도착 성공을 같은 정답으로 취급하지 않는다.
- 기존 2,729개 코호트를 주 비교 대상으로 유지한다. 새로 개설된 대여소의 일반화는 별도 과제로 둔다.
- 현재 양수 구간, 현재 1~3대 구간, 출퇴근·휴일·우천 구간을 사전 보조 분석으로 정한다.
- 전체 F1·정밀도·재현율·AP·Brier·오경보·놓침과 각 구간의 분모를 함께 기록한다.
- 보조 구간의 큰 개선을 전체 목표 달성으로 바꾸지 않는다. +5%p는 기존 팀 목표로 유지하며 학교 합격선으로 표현하지 않는다.

## 2. 비교 모델을 미리 정한다

| 기준 | 구성 | 역할 |
| --- | --- | --- |
| B0 | 현재 0대 여부 유지 | 학습 없이 얻는 수준을 확인한다. |
| BS | 전일·전주 규칙과 학습 기간의 평활 전환 빈도 | 시간 구조를 이용한 단순 기준을 확인한다. |
| BL | 로지스틱 회귀 | 저비용 확률 모델과 비교한다. |
| BRF | Random Forest | 수량 예측 문헌의 일반적인 비선형 방법을 대표한다. |
| BGB | LightGBM·CatBoost·XGBoost 중 검증에서 선택한 단일 모델 | 충분히 조정한 트리 기준과 비교한다. |
| B1-refit | 기존 자기 대여소 중심 B1을 같은 기간에 재학습 | 이전 설명과의 연속성을 유지한다. |
| M2-refit | 기존 LightGBM+CatBoost 50:50 구조를 같은 기간에 재학습 | 기존 최종 챔피언을 새 방법의 필수 대조군으로 유지한다. |
| M-new | 우선순위 단계에서 선택한 제안 후보 | 새로운 정보·구조의 추가 이익을 검증한다. |

RF와 부스팅의 채택 근거는 자전거 가용 수량·흐름 연구에서 실제 사용한 방법이라는 점이다. ARIMA·Prophet은 추가 수량 회귀 기준으로 검토하되, 이미 관측된 다음 0대 여부를 직접 분류하는 기준을 대신하지 않는다. [가용 수량 연구](https://arxiv.org/abs/2006.08352), [여러 도시의 방법 비교](https://pmc.ncbi.nlm.nih.gov/articles/PMC10556600/)

같은 모델 효과 비교에서는 기간·정답·표본·정보 집합을 맞춘다. 과거 데이터 확장 효과를 따질 때는 같은 학습기를 사용한다. 탐색 수·표본 제한·조기 종료 방식과 실제 실행 시간을 기록하며, 서로 다른 비용으로 탐색했다면 동일한 예산이라고 주장하지 않는다.

## 3. 기간을 나눈다

기존 2025-03-15~03-31과 2025-04-15~05-14는 이미 점수를 확인한 기간이다. 개발 자료로 재사용할 수 있으나 새 독립 시험이라고 부르지 않는다.

아래 날짜는 새 원본의 스키마·누락 검수와 사용 이력 확인을 마친 뒤 확정할 설계안이다. 아직 실행용 설정으로 고정하지 않는다. 입력 시각이 아니라 **정답 시각**으로 학습·검증 소속을 나눈다.

| 개발 폴드 | 학습 정답의 마지막 날짜 | 조기 종료 선택 | 확률 보정 | 임계값·정책 선택 | 바깥 개발 검증 |
| --- | --- | --- | --- | --- | --- |
| A | 2025-04-30 | 05-01~05-07 | 05-08~05-10 | 05-11~05-14 | 05-15~05-31 |
| B | 2025-05-14 | 05-15~05-21 | 05-22~05-25 | 05-26~05-31 | 06-01~06-14 |
| C | 2025-05-31 | 06-01~06-07 | 06-08~06-10 | 06-11~06-14 | 06-15~06-30 |

학습 시작은 비교에 따라 최근 56·112일 또는 확보한 전년도 자료까지로 설정한다. 이전 폴드 검증 자료가 다음 폴드에서 과거 자료가 되는 순차 구조를 허용한다. 세 개발 검증의 결과로 후보를 선택하므로 이들 기간의 최고 점수를 최종 일반화 성능으로 제시하지 않는다.

- 2025년 3분기는 선택된 학습·갱신 절차를 고정한 뒤 확인할 이후 기간 검증 후보로 남긴다.
- 2025년 4분기는 최종 봉인 시험 후보로 남긴다. 3분기를 열고 절차를 수정하면 3분기는 개발/검증으로 재분류한다.
- 4분기를 열기 전에 데이터 버전·코호트·모델·특징·재학습 일정·임계값 갱신·보정·추천 정책·지표를 모두 기록하고 해시를 남긴다.
- 온라인 갱신을 평가할 경우 사전에 정한 일정으로 이미 도착한 과거 정답만 사용한다. 고정 모델 평가와 적응 모델 평가를 별도 표로 보고한다.
- 최종 시험의 성능을 보고 다시 튜닝한 뒤 같은 기간을 새 독립 시험으로 제시하지 않는다.

무작위 행 분할을 사용하지 않는다. 다중 대여소에서는 같은 시각의 모든 대여소를 같은 시간 블록에 넣는다. 필요한 간격은 예측 선행 시간과 정답 도착 지연으로 정한다. 이미 관측된 과거 이력을 검증 입력으로 사용하는 것 자체를 누수로 보지는 않으며, 전처리·스케일러·그래프·정적 타깃 인코딩의 적합 범위를 함께 확인한다. [공식 시간 분할 문서](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html), [자전거 시차 특징 예제](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html)

## 4. 정보 시점을 따로 검증한다

| 입력 구분 | 주 비교에서의 처리 |
| --- | --- |
| 수량 관측·기록된 상태·공표된 달력 | 원천 시각과 지연 조건을 기록해 사용한다. |
| 예보·공연 일정·과거 통계 | 발표일·등록일·원본 버전이 입력 시각 이전인지 확인한다. |
| 사후 ASOS·AWS·대여이력·유동인구 | 당시 공개 가능성이 입증되지 않으면 아카이브 보조 실험으로 분리한다. |
| 다음 시각 실제 날씨·미래 OD·사후 운영 상태 | 예측 입력으로 사용하지 않는다. |

엄밀한 운영 입력 비교와 아카이브 조건의 상한 탐색을 별도 표로 둔다. 아카이브 실험에서 추가 정보가 도움이 되면, 그 정보를 실제로 확보할 수 있는 수집 경로나 예보 대체재가 필요한 것으로 해석한다.

기존 날씨 포함 M2-refit은 동일 아카이브 입력을 사용하는 비교에서 그대로 유지한다. 운영 입력 비교에서는 제공 시점이 확인된 기상만 허용하며, 미검증 기상을 제외한 변형은 `M2-no-weather`로 별도 표기한다. 입력 조건이 다른 두 표의 점수를 직접 합쳐 우열을 주장하지 않는다.

## 5. 실험 단계를 구성한다

| 단계 | 실험 묶음 | 선택 기준 |
| --- | --- | --- |
| E0 | 데이터 정의·누락·중복·대여소 연결·제공 시점 점검 | 잘못된 정답과 미래 정보가 없음을 먼저 확인한다. |
| E1 | B0·BS·BL·BRF·BGB·B1-refit·M2-refit | 새 기간에서 기존 수준과 강한 대조를 확보한다. |
| E2 | 56·112일 창, 주간 갱신, 전년도 요약, 공휴일 | 동일 모델에서 자료 기간과 갱신 효과를 분리한다. |
| E3 | 과거 OD·다지점 기상·발표된 예보 | 입력 제공 시점이 확인되는 후보부터 하나씩 추가한다. |
| E4 | STID·긴 입력 TCN·TabM·순서형/공동 목표·NB | 트리와 다른 오류를 만드는지 확인한다. |
| E5 | 희소 STGCN·Graph WaveNet과 거리/OD 제거 비교 | 실제 그래프 구조가 집계 특징보다 도움이 되는지 확인한다. |
| E6 | 시간 외부 예측 스태킹·조건별 혼합 | 단일 후보보다 일관된 이익이 남을 때 결합한다. |
| E7 | 기반 모델·더 큰 Transformer | 남은 오류와 비용이 정당화할 경우 보완 후보로 진행한다. |
| E8 | 선택 고정·이후 기간 검증·최종 시험 | 선택 이후의 성능과 한계를 기록한다. |

각 후보는 먼저 고정된 개발 기간의 대표 표본에서 실행 가능성만 점검한다. 시간대·대여소·수량 상태의 분포를 보존해 표본을 구성하고, 표본에서의 순위를 전체 자료 성능으로 확정하지 않는다. 최종 후보는 동일한 전체 검증 자료와 최종 시험 분모로 비교한다.

## 6. 계산 자원을 현실에 맞춘다

실제 PC는 RAM 약 15.7GiB이고 CUDA GPU를 확인하지 못한다. 모델 실험을 수행할 경우 CPU 4스레드·동시 학습 1개와 모델 프로세스 약 8~9GiB를 초기 상한으로 제안한다. 이 수치는 실측한 학습 메모리가 아니라 실행 전에 조정할 자원 계획이다.

- 2,729개 대여소×24시간×500일×116개 float32 특징만으로 약 14.15GiB를 차지한다. 전체 기간을 거대한 pandas 행렬 여러 개로 복사하는 계획을 세우지 않는다.
- 최근 56·112일 자료부터 비교하고, 전년도 자료는 요약·부분 학습·디스크 기반 배치를 검토한다. 기간을 줄이는 실험과 기간을 확장하는 실험을 별도로 기록한다.
- 월별 청크·메모리 매핑·분류형 압축을 검토하고 최대 RSS와 처리 시간을 기록한다. 이 자료 처리 코드는 이번 조사에서는 구현하지 않는다.
- 일반적인 명시적 공간 attention의 경우 `batch 8×12시점×4헤드×2729²×4바이트`만 약 10.65GiB이다. 역전파·다른 활성값 전의 계산이며 모든 구현의 실제 피크와 같지는 않다.
- 전체 밀집 attention을 기본값으로 정하지 않고 희소 이웃·작은 배치·지역 묶음·효율적인 연산을 검토한다. 학습한 지역 묶음도 검증·시험의 모든 대여소를 빠뜨리지 않게 평가한다.
- 신경망은 기존 8에포크 제한과 달리 조기 종료·최대 학습 예산을 미리 기록한다. CPU 파일럿 없이 이 PC에서의 소요 시간을 논문 수치로 단정하지 않는다.
- 별도 패키지·체크포인트가 필요한 후보는 기존 고정 환경을 보존하는 독립 실험 환경으로 계획한다. 이번에는 설치하거나 라이선스 수락을 진행하지 않는다.

## 7. 채택과 종료 판단을 정한다

주 지표는 전체 F1로 유지하되, 현재 양수 구간 전환 위험의 AP·재현율·오경보와 확률 품질도 함께 본다. 우선 개발 폴드 전반의 안정적인 개선을 찾으며 한 날짜·한 초기값의 최고값만 선택하지 않는다.

- 고정된 후보 비교에서 평균 F1 개선, 기간별 편차, 재현율 악화 여부와 계산 비용을 함께 판단한다.
- 실험 반복 변동과 비교할 실용적 차이를 사전에 정한다. 설계상의 후보 기준으로 +0.2%p 정도를 검토하되 이 값 자체를 성능 달성 결과나 학교 요구로 주장하지 않는다.
- 최종 후보는 여러 초기값과 날짜 단위 짝비교를 점검한다. 주간 의존성을 고려한 블록 재표집과 월별 표를 함께 제시한다.
- 많이 탐색한 개발 점수의 신뢰구간은 선택 편향을 없애지 못한다. 채택된 절차의 최종 평가는 봉인 시험에서 수행한다.
- 큰 복잡도 증가에 비해 차이가 불분명하거나 일부 구간의 오경보가 커지면 단순한 기존 모델을 유지하는 선택도 허용한다.
- 한 실험 묶음이 실패하면 근거를 기록하고 다음 정보·모형 가설로 진행한다. 같은 자료·같은 구조의 미세 조정을 무한 반복하지 않는다.
- 주요 우선순위 가설을 검증하고 추가 이익이 실험 변동보다 작아지면 시도한 범위의 한계로 보고한다. 모든 가능한 방법의 전역 최적점을 증명했다고 표현하지 않는다.

이 계획은 앞으로 무엇을 시험해야 하는지 정리한다. 이번 조사만으로 추가 성능 향상, 기존 목표 달성, 최종 모델 선택이 완료된 것은 아니다.

## 8. 추천까지 평가할 때의 조건

모델만 비교하는 주 실험과 추천 정책 실험을 구분한다. 추천을 다시 확인할 때는 동일 출발지·시간·반경·직선거리 정의와 보류 포함 분모를 사용한다.

- R0 최근접 양수, Rq 현재 수량·거리, 같은 효용의 기존 B1/M2, 새 모델을 같은 규칙에서 비교한다.
- 모델이 바뀐 효과와 위험·거리 가중치가 바뀐 효과를 나눠 제시한다.
