# 데이터 조사와 사용 우선순위

조사일: 2026-10-20. 우선순위는 기대되는 정보량, 정답과의 관련성, 실제 확보 가능성, 입력 시점과 비용을 종합한 판단이다. 성능 개선이 확인됐다는 뜻으로 사용하지 않는다.

## 제공 시점이 성능보다 먼저 해결돼야 하는 이유

ASOS 포털은 전일 자료를 당일 10시 이후 확인할 수 있다고 안내한다. 이는 모든 별도 실시간 API의 지연이 동일하다는 뜻은 아니지만, 현재 내려받은 아카이브에 단순히 1시간 시차를 주었다는 이유만으로 당시 실시간 이용 가능성을 입증할 수 없음을 보여준다. 기존 M2의 기상 결과는 아카이브 기반 민감도 분석이라는 범위를 유지한다. [기상청 공식 자료 설명](https://data.kma.go.kr/data/grnd/selectAsosRltmList.do)

후속 설계에서는 입력마다 `event_time`, `published_at`, `received_at`, `version`, `max_lookahead`를 구분한다. 공개 시점이 확인되지 않은 자료는 사후 자료 실험으로 분류하거나 보수적인 이전 기간 통계로 제한한다. 제공되지 않은 당일 OD, 사후 확정된 유동인구, 다음 시간 관측 날씨를 섞어 성능을 높이지 않는다.

## 데이터 추가 전 점검할 항목

- `거치대수량` 등 열의 실제 의미와 집계 방법을 이전 파일·공식 안내와 대조한다.
- 날짜·시간대의 범위, 24시 표현, 시간대와 중복 키를 확인한다. 서울 시간 기준을 고정한다.
- 결측을 0대로 바꾸지 않고 정확히 다음 격자의 실제 관측이 있는 경우만 정답을 구성한다.
- 대여소 번호 재사용·이전·개설일과 2024년 과거 위치를 확인한다. 현재 위치를 과거 모든 날에 소급하지 않는다.
- 저수량과 임시 폐쇄·수신 실패를 같은 의미로 처리하지 않는다. 확인할 운영 상태가 없으면 제약으로 남긴다.
- 대여·반납의 순유입과 수량 변화가 달라도 곧바로 오류로 삭제하지 않는다. 재배치·정비·관측 시점 차이 가능성을 검토한다.
- 거치대 수를 물리적 엄격 상한으로 가정하지 않는다. 연결 거치·운영 방식과 자료 정의를 먼저 확인한다.
- 각 입력의 효과는 같은 기간·같은 정답·같은 모델에서 하나씩 추가하는 비교로 확인한다.
