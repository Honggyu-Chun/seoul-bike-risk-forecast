# 추가 데이터 조사·수집 기록

2026-10-20에 저장한다. 전원 종료에 대비해 새 네트워크 요청을 중단한다. 모델 학습은 이 작업에서 실행하지 않는다. API 키를 문서·코드·기록에 넣지 않는다.

## 바로 확인할 결론

실시간 예측에 맞는 추가 후보로 서울 자치구 대기질과 GFS의 이전 예보 입력을 확인한다. 두 제공자의 현재 응답을 실제로 받아 미래 예측 시점에 사용할 수 있는 경로를 점검한다. 현재 접속 성공과 2025년 당시 공개본의 재현은 서로 다른 검증으로 다룬다. 과거 자료만 있는 후보를 실시간 모델의 확정 입력으로 올리지 않는다.

| 자료 | 실제 확보 | 실시간 적격성 판단 |
| --- | --- | --- |
| 서울 자치구 대기질 | 2025 연간 ZIP, 상반기 정제 108,600행, 현재 25구 응답 1회 | 현재 API 활성과 약 60분의 관측 시각 차이를 확인한다. 보수적 지연·수신 시각·결측 규칙을 적용할 조건부 후보로 둔다. |
| Open-Meteo GFS 이전 예보 | 5격자×4,344시간×5항목, 현재 미래 예보 응답 1회 | 현재 목표 시각 이전에 예보를 받는 경로를 확인한다. 2025년 개별 실행·발표 시각의 불확실성을 남긴다. |
| KMA AWS | 공식 자료 제공 설명을 검토한다. 신규 원본은 수집하지 않는다. | 별도 기상청 계정·인증과 관측소 이력·배포 지연 검수가 필요하다. |

## 서울 대기질의 수집과 품질

[서울 공식 OA-2221](https://data.seoul.go.kr/dataList/OA-2221/S/1/datasetView.do)의 2025 ZIP을 내려받는다. 파일 수정일은 2026-04-01로 확인한다. 출처표시 조건을 적용한다. 원본 ZIP은 2,910,118바이트이며 CRC를 통과한다. 출처·SHA-256·수신 시각은 `air_download_manifest.json`에 저장한다.

2025년 1~6월의 4,344시간과 25개 구를 연결해 108,600행을 구성한다. 시간×구의 중복·충돌·누락 행은 각각 0으로 확인한다. 모든 대여소 2,729개가 구명으로 연결된다. 구의 측정값을 각 대여소 바로 옆의 센서 관측값처럼 해석하지 않는다.

항목의 빈 값은 별도로 보존한다. PM10 3,550건(3.27%), PM2.5 3,403건(3.13%), O3 1,988건(1.83%), NO2 1,531건(1.41%), CO 1,629건(1.50%), SO2 2,147건(1.98%)을 결측으로 확인한다. 관악구 PM10·PM2.5는 결측률이 높아 구별 표를 함께 확인한다. 음수·비유한값·숫자 해석 실패는 상반기에서 발견하지 않는다. 높은 농도만을 이유로 임의 삭제하지 않는다.

원본에는 제공자의 품질 판정 열이 없다. 자체 `_qc`는 0=존재·유한·비음수, 1=결측, 2=음수·비유한, 3=숫자 해석 실패, 4=충돌 중복으로 정의한다. 0을 제공자가 정상으로 인증한 값이라는 뜻으로 사용하지 않는다. 앞채움이나 미래 보간을 수행하지 않는다.

## 현재 API를 실제로 확인한 결과

[OA-1200의 공식 API 탭](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-1200&srvType=A&infSeq=1)은 현재 `ListAirQualityByDistrictService`를 안내한다. 이 명세에 맞춰 25개 구를 1회 조회하고 `INFO-000`을 받는다. `RealtimeCityAir`라는 이전 명칭과 현재 명세를 혼동하지 않는다.

2026-10-20 16:00:07.720622 KST에 받은 25개 구의 `MSRMT_YMD`는 모두 15:00으로 확인한다. 관측 시각부터 수신까지 60.1287분 차이를 기록한다. 이 한 번의 관측으로 평소 최대 지연이나 장애 빈도를 보장하지 않는다. 제공자의 최초 공개 시각은 응답에 없다.

| 현재 응답 | 과거 정제 열 | 단위 |
| --- | --- | --- |
| `MSRMT_YMD` | `timestamp` | 서울 시간의 측정 시각 |
| `MSRSTN_NM` | `district` | 구명 |
| `PM`, `FPM` | `pm10_ug_m3`, `pm25_ug_m3` | ㎍/㎥ |
| `OZON`, `NTDX` | `o3_ppm`, `no2_ppm` | ppm |
| `CBMX`, `SPDX` | `co_ppm`, `so2_ppm` | ppm |

운영 후보 규칙은 입력 시각 t에서 2시간 또는 3시간 전 관측만 사용하고, 실제 `received_at≤t`인 스냅샷만 채택하는 방식으로 제안한다. 늦거나 없는 값은 결측으로 둔다. 최신 응답만 제공하는 API에서 24시간 전 값을 쓰려면 과거에 받은 스냅샷을 로컬에 축적해야 한다. 이 작업은 단일 응답만 저장하며 자동 반복 수집을 시작하지 않는다. 2025 확정본에 시차만 주는 것으로 과거 당시 값의 수정 이력까지 입증하지 않는다.

## GFS 예보의 확인 결과

[Previous Runs 공식 문서](https://open-meteo.com/en/docs/previous-runs-api)의 `_previous_day1` 계열로 24시간 선행 오프셋을 고정한다. 서울 중심·북서·북동·남서·남동의 5개 요청 지점이 서로 다른 반환 격자로 연결된다. 2025년 상반기의 기온·강수·습도·풍속·운량 21,720행에서 결측이 0임을 확인한다. 각 대여소는 요청 좌표가 아닌 실제 반환 격자 중 가장 가까운 지점에 연결한다.

같은 API의 현재 조회로 2026-10-20 16:00:08.853585 KST에 미래 유효 시각의 예보를 수신한다. 예를 들어 18:00 유효 예보를 그 전에 받는 경로를 확인한다. 이 자료를 1시간 선행으로 생성된 기상 예보라고 부르지 않는다. 자전거의 t+1 예측에 더 오래 전에 생성된 기상 예보를 사용하는 구조로 설명한다.

[실행별 문서](https://open-meteo.com/en/docs/single-runs-api)는 초기화와 공개 시각을 구분하며, 일반 모델의 실행별 보존을 2026-04-02부터 안내한다. 따라서 GFS의 2025년 개별 실행을 이 서비스로 전부 검증했다고 주장하지 않는다. 현재 응답에도 개별 실행 초기화·최초 공개 필드가 없다. [갱신 문서](https://open-meteo.com/en/docs/model-updates)의 실제 API 제공 시각 필드와 서버 간 전파 여유 10분을 운영 검수의 추가 조건으로 기록한다. 이번 종료 시점까지 실행별 메타데이터 API의 실제 응답과 교체 경계는 확인하지 않는다.

[이용약관](https://open-meteo.com/en/terms)의 비상업 교육·연구용 무료 API 및 CC-BY 4.0 조건을 확인한다. 소량 요청으로 제한한다. 비용 결제나 유료 가입을 진행하지 않는다.

## 운영 입력 선택을 구현한 방법과 이유

새 네트워크 요청 없이 저장한 명세·응답으로 `bike_demo/followup_v4/operational_inputs.py`를 구현한다. 자료를 조회하거나 학습하는 코드와 구분해, 이미 저장된 스냅샷과 입력 요청만 받아 선택한다. 공급자 관측 시각과 컴퓨터 수신 시각을 두 개의 독립 조건으로 다룬다. 공식 명세에 없는 시각을 추정해 추가하지 않는다.

이 선택 규칙은 논문 모델의 재현 성과가 아니라, 실시간 예측의 시점 누출을 막기 위한 데이터 구성 방법으로 설명한다. OA-1200 저장 명세의 측정 시각 필드와 실제 수신 기록을 근거로 구현한다. 앞서 검토한 [순방향 시계열 검증](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)이 미래 학습을 피하더라도, 각 입력의 나중 수신·수정본까지 자동으로 막아 주지는 않는다는 판단을 함께 적용한다. [기상 예보 시각 문서](https://open-meteo.com/en/docs/model-updates)의 초기화·변환·제공 시각 구분도 같은 원칙의 근거로 삼는다.

| 처리 | 채택한 방법과 이유 | 검토한 대안·한계 |
| --- | --- | --- |
| 수신 시각 | `received_at≤t`인 응답만 선택한다. 예측 이후에 받은 과거 관측과 나중 수정본의 누출을 막는다. | 관측 시각만 검사하면 나중에 내려받은 수정값을 당시 알던 값처럼 사용할 수 있다. |
| 관측 시각 | `timestamp≤t-2h` 또는 3h로 제한한다. 저장 응답의 약 60분 지연에 추가 여유를 둔다. | 2·3시간은 보수적인 정책값이며 최대 지연의 실측 보장이 아니다. 장기 지연 기록에 따라 다시 조정해야 한다. |
| 최대 나이 | 기본 6시간 이내의 관측만 선택한다. 오래된 값이 계속 입력되는 일을 막는다. | 6시간은 성능으로 최적화한 수치가 아니다. 허용하는 지연과 서비스 품질에 맞춰 정하고 같은 규칙으로 비교해야 한다. |
| 시점 선택 | 허용 구간 안에서 가장 최근 관측을 고르고, 같은 관측에서는 t 이전에 수신한 마지막 수정본을 고른다. | 정확히 t-2h인 행만 고르는 방법보다 결측을 줄일 수 있지만 실제 자료 나이가 달라진다. 반환하는 `source_age_hours`를 함께 확인한다. |
| 품질·결측 | 선택한 관측의 항목별 값을 검사하고 쓸 수 없는 항목만 NaN으로 돌린다. | 최신 값이 점검 중이라고 이전 정상 값을 조용히 가져오지 않는다. 항목별 다른 시각의 대체값을 허용하려면 나이·수신 시각까지 따로 설계해야 한다. |
| 중복 | 관측·수신 시각이 모두 같은데 값이 다르면 해당 스냅샷을 거부한다. | 파일 순서나 마지막 행을 임의 정답으로 고르지 않는다. 동일한 중복 행은 한 응답으로 취급한다. |
| 시각 오류 | 관측 시각이 수신 시각보다 미래이면 관측 입력에서 제외한다. | 예보의 미래 유효 시각은 정상적인 별도 의미이므로 이 관측 전용 함수에 예보를 넣지 않는다. |
| 보간 | 미래 값 보간·무제한 앞채움·결측의 0 대체를 하지 않는다. | 모델이 결측을 처리하도록 하되 결측 자체와 실제 0을 구분한다. |

`max_observation_age`는 최소 시차보다 작게 설정할 수 없고, 최소 시차는 2시간보다 짧게 설정할 수 없도록 검사한다. 24시간 전의 입력을 같은 함수로 고르려면 최소 시차와 최대 나이를 모두 그 목적에 맞춰 명시하고, 실제 과거 수신 캐시가 있는지 확인한다.

### 함수의 입력·출력과 단위

`select_observed_inputs()`의 스냅샷은 `timestamp`=공급자의 관측 시각, `received_at`=실제 로컬 수신 완료 시각, `district`=구명, 수치 열로 구성한다. 요청은 `input_time`=예측 입력 시각과 `district`로 구성한다. 시간대가 없는 시각은 명시한 기본값 Asia/Seoul로 해석하고, 반환 시각은 UTC 시간대가 있는 값으로 통일한다. 요청 행의 순서와 인덱스를 보존한다.

수치 단위는 바꾸지 않는다. `pm10_ug_m3`, `pm25_ug_m3`는 ㎍/㎥를 사용하고 `o3_ppm`, `no2_ppm`, `co_ppm`, `so2_ppm`는 ppm을 사용한다. 함수는 CAI나 등급을 농도 값으로 바꾸지 않는다. 공급자의 `MSRMT_YMD` 원문은 호출 전에 `%Y%m%d%H%M`으로 명시적으로 해석한다.

반환하는 `source_timestamp`, `source_received_at`, `source_age_hours`로 실제 선택 근거를 확인한다. `timing_eligible`는 두 시각 조건을 통과했다는 의미로 사용한다. `operational_eligible`는 시각 조건을 통과하고 요청 수치 중 적어도 하나를 사용할 수 있다는 뜻으로 사용한다. 각 수치의 `<수치명>_usable`도 함께 확인한다. 이 표시는 해당 저장 응답을 해당 입력 시각에 사용하는 조건이며 모델 전체의 운영 적합성이나 과거 실시간 성능을 인증하지 않는다.

품질 열 `<수치명>_qc`가 있으면 0인 항목만 허용한다. 없으면 로컬 수치 검사를 수행한다. 자체 코드는 0=존재·유한·비음수, 1=빈 값, 2=음수·비유한, 3=점검 중 등 숫자로 해석할 수 없는 값, 5=제공된 QC 값을 해석할 수 없는 경우로 표시한다. 공급자 QC가 없는 자료의 0을 정상 인증으로 해석하지 않는다.

```python
import pandas as pd
from bike_demo.followup_v4.operational_inputs import (
    select_observed_inputs, tag_archived_features,
)

snapshots = pd.DataFrame({
    "timestamp": ["2026-10-20 15:00:00+09:00"],
    "received_at": ["2026-10-20 16:00:07.720622+09:00"],
    "district": ["종로구"],
    "pm10_ug_m3": [26.0],
    "pm25_ug_m3": [15.0],
})
requests = pd.DataFrame({
    "input_time": ["2026-10-20 17:00:00+09:00"],
    "district": ["종로구"],
})
selected = select_observed_inputs(
    snapshots, requests, ["pm10_ug_m3", "pm25_ug_m3"],
    min_observation_lag="2h", max_observation_age="6h",
)
# 15시 관측을 17시 입력에서 선택하고 실제 자료 나이 2시간을 반환한다.

archive = pd.read_parquet(
    r"D:\P실무\모델개발\data\raw\followup_v4_extra\model_ready\air_2025h1_input_lags2_3_24.parquet"
)
labelled_archive = tag_archived_features(archive)
# 값은 보존하며 reception_status='archived_reception_unknown'으로 표시한다.
```

### 과거 학습과 실시간 재고 API의 한계

역사 학습용 lag2·3·24 표의 `timestamp`는 이미 입력 t이다. 공급자 관측 시각을 뜻하는 원본 스냅샷의 `timestamp`와 혼동해 관측 선택 함수에 그대로 넣지 않는다. 이 표에는 당시의 `received_at`이 없으므로 `tag_archived_features()`로 `archived_reception_unknown`을 보존한다. 수신 시각을 만들지 않고 운영 필터를 통과했다고 표시하지 않는다. 같은 정보를 얻을 수 있는 현재 API 경로가 존재하므로 조건부 학습·개선 시험의 후보로 사용할 수 있지만, 그 시험을 과거 실시간 운영 성능으로 확정하지 않는다.

따릉이 공급자 응답에 관측 시각이 없다면 로컬 수신 시각을 관측 시각으로 복사하지 않는다. `received_at`은 실제 받은 시각으로 기록하고 공급자 관측 시각은 미상으로 남긴다. 이 함수는 `observation_time_unknown`으로 반환한다. 수신 시각만으로 동작하는 별도 경로를 검토하더라도 자료 나이의 보장과 관측 시각이 확인된 경로를 구분해야 한다.

### 실행 검수 결과

`tests/test_operational_inputs.py`의 21개 검사를 통과한다. 미래 관측·늦게 수신한 과거값·미래 수정본·2/3시간 경계·최대 나이·점검 중·부분 결측·QC 미상·중복 충돌·시간대·구 분리·미상 시각을 검사한다. 모델 학습과 네트워크 호출은 포함하지 않는다.

저장된 현재 25구 응답을 2026-10-20 17:00 KST의 입력에 실제 적용한다. 시간 조건은 25개 구가 통과하지만, 성북구·은평구·강동구 3개 구의 모든 농도가 원문 `점검중`이므로 NaN으로 제외하고 22개 구만 수치 사용 가능으로 반환한다. 기존 수집 audit의 빈 문자열 수가 0이라는 사실만으로 25개 구 모두 정상 수치라고 해석하지 않는다. 나머지 선택 자료의 나이는 모두 2시간으로 확인한다.
