# 후속 실제 실험 v4

2026-10-21 등록한 53개 비교와 별도 공공데이터 9개 비교를 완료한다. [쉬운 완료 보고서](쉬운보고서.html), [최종 수동 검수](final_manual_review.json), [추가 자료 실제 비교](../20261020_추가공공데이터적용/추가공공데이터_비교보고서.html)를 우선 확인한다. 아래 실행 안내는 재현과 새 요청을 위한 설명이며 완료 모델을 다시 학습할 필요는 없다. 미개봉 3·4분기는 이번 완료 범위에 포함하지 않는다.

사용자의 새 요청에 따라 조사·설계를 실제 구현·학습·비교 단계로 확장한다. 기존 고정 결과와 제안서는 보존한다.

## 먼저 볼 파일

- `실험결과.md`: 완료 결과와 미실행 항목을 구분한다. 집계 명령으로 갱신한다.
- `leaderboard.csv`: 완료 후보별·폴드별 지표, 시간, 정보 조건을 기록한다.
- `protocol.json`: 새 비교 전에 고정한 정답·기간·보정·정책 선택 절차를 기록한다.
- `API와추가데이터.md`: 실제 인증·수집 상태, 명세 대조와 자료 제약을 설명한다.
- `run_priority.ps1`: 완료 후보를 건너뛰며 순차 실험을 재개한다. 동시에 두 번 실행하지 않는다.

## 정답과 검증 기간

정답은 정확히 다음 1시간 격자에서 관측 수량이 0인지로 정의한다. 현재와 다음 관측이 모두 있는 행만 평가한다. 기존 코호트 2,729개 대여소를 유지한다. 결측을 0으로 바꾸지 않는다. 기간 소속은 정답 시각으로 결정한다.

| 폴드 | 학습 정답 마지막 날 | 조기 종료 | 확률 보정 | 임계값 선택 | 바깥 개발 검증 |
| --- | --- | --- | --- | --- | --- |
| A | 04-30 | 05-01~07 | 05-08~10 | 05-11~14 | 05-15~31 |
| B | 05-14 | 05-15~21 | 05-22~25 | 05-26~31 | 06-01~14 |
| C | 05-31 | 06-01~07 | 06-08~10 | 06-11~14 | 06-15~30 |

연도는 모두 2025년으로 한다. 최근 56일을 기본 창으로 사용하며 112일 창을 별도 비교한다. A/B/C는 개발·선택용으로 사용한다. 2025년 3·4분기 점수는 열지 않는다. 기존 4월 15일~5월 14일을 새 독립 시험으로 제시하지 않는다.

## 실행 순서

1. 상태 유지·전일·전주·평활 Markov·로지스틱·Random Forest·기본 LightGBM을 A/B/C에서 비교한다.
2. LightGBM·CatBoost·XGBoost와 기존 결합의 50:50 구조를 새 기간에서 재학습한다. 실시간 경로가 미확인인 기상 입력을 뺀 `M2_no_weather`를 현재 주 대조군으로 사용한다. 같은 73개 시간 특징을 사용하는 세 부스팅 모델도 비교한다.
3. 창 길이·최근성·잎 수·순서형·Poisson·상태 전문가를 A에서 우선 비교한다. 개선 후보를 다른 폴드에서 확인한다.
4. 같은 LightGBM에 공휴일·전년도·KBO 원래 일정을 각각 추가한다. 문화행사는 수집 자료와 제약을 보존하고 주 학습 큐에서는 제외한다. 대기질 2·3시간 전과 이전 날 GFS 예보는 현재 수신 경로가 확인된 조건부 추가 비교로 분리한다.
5. 24·168시간 MLP, 24시간 TCN과 5개 이웃 신호를 결합하는 TCN을 비교한다. 같은 그래프 모델의 자기 자신 연결 대조군도 둔다. 30만 학습 표본·최대 20에포크·조기 종료를 사용하는 CPU 예비 비교로 기록한다. 논문 전체 재현으로 부르지 않는다.
6. 개선된 예비 후보를 사전 지정 기준으로 B/C에서 확인하고, 저장 모델의 예측 재현과 기존 원본 보존을 검수한다.

최초 비교는 초기값 하나로 수행하며 최종 채택과 구분한다. 기반 모델·큰 Transformer·새 OD 자료는 비용과 제공 시점이 확인될 때 후속 조건부 후보로 남긴다. 조사 목록 48개를 독립 학습 모델 48개로 표현하지 않는다.

## 코드·산출물·재개

새 코드는 `bike_demo/followup_v4`에 격리한다. `data_audit.py`는 원본을 검수하고, `features.py`는 기존 특징을 디스크 행렬로 구성한다. `runner.py`는 기준 모델을 실행한다. `context.py`·`advanced.py`는 추가 자료와 앙상블을 비교하고, `neural.py`는 신경망 예비 비교를 실행한다. `external_data.py`는 공개 API를 조회한다.

대용량 행렬·모델·예측은 `artifacts/followup_v4_20261020`, 원본 API 응답은 `data/raw/followup_v4_external`에 저장한다. 대용량 자료와 `.env`는 Git에서 제외한다. 키를 보고서나 로그에 기록하지 않는다. 학습은 한 프로세스·CPU 4스레드로 순차 실행한다.

```powershell
Set-Location -LiteralPath 'D:\P실무\모델개발'
& '.\experiments\20261020_후속실험_v4\run_priority.ps1'
& '.\.venv\Scripts\python.exe' -X utf8 -m bike_demo.followup_v4.report
```

진행 후보는 `artifacts/followup_v4_20261020/worker.json`과 로그에서 확인한다. 성공 JSON이 있는 후보만 완료로 집계한다. 오류 JSON 뒤에 성공 JSON이 생성된 경우 성공 이력을 우선 확인한다.

## 분석 결과 갱신과 완료 검토

`결과갱신.ps1`은 저장 모델 재로딩, 평가표, 세부 오류, 날짜 블록 범위, 쉬운 보고서, 체크포인트와 완료 검토를 순서대로 갱신한다. 새 학습을 시작하는 명령으로 사용하지 않는다. 실행 중 큐가 끝난 뒤 한 번 수행해 최신 결과 전체가 검수에 포함됐는지 확인한다.

`completion_review.json`은 등록한 최소 53개 후보×기간 조합과 후속 확인 대상, 파일·모델·전체 기준 비교·확률 캐시·기존 파일 보존을 대조한다. 누락이 없어도 최종 문장·그림·실제 프로세스 종료·미개봉 시험 보존을 수동 검토하기 전에는 목표 완료로 기록하지 않는다. 비교 수를 독립 모델 수로 표현하지 않는다.

날짜별 오류와 1·7일 묶음 2,000회 재표집 결과는 `E2E/06_평가`에 저장한다. 개발 성과를 본 뒤 추가한 탐색적 변동 분석이며 최종 시험 우월성 증명으로 사용하지 않는다. 코드·규칙·원본 집계 일치는 `uncertainty_plan.json`, `uncertainty_checks.json`에 남긴다.
