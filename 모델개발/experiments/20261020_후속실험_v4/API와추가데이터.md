# API 연결과 추가 데이터

두 키를 `D:\P실무\모델개발\.env`에 저장한다. `KOPIS_API_KEY`, `SEOUL_API_KEY`로 읽으며 `.env.example`에는 빈 예시만 둔다. 키를 출력하지 않고 성공 여부와 비밀정보를 제외한 요청 조건만 기록한다.

## KOPIS 명세 대조

사용자가 `D:\P실무\참고자료\KOPIS`에 추가한 개발가이드 32쪽과 공통코드 58쪽을 확인한다. 개발가이드 버전은 5.0, 배포일은 2026-04-23으로 확인한다. 원본 PDF를 보존한다.

| 목적 | 서비스·연결 | 활용 |
| --- | --- | --- |
| 공연 목록 | `pblprfr`, `mt20id` | 서울 공연을 월별로 조회하고 ID로 중복을 제거한다. |
| 공연 상세 | `pblprfr/{mt20id}` | 날짜·`dtguidance`·`prfruntime`·`frstregdt`·`updatedate`를 보관한다. |
| 공연시설 상세 | `prfplc/{mt10id}` | 위도 `la`·경도 `lo`와 좌석 규모를 연결한다. |
| 공연장 구분 | `mt13id` | 시설 전체 좌석과 개별 공연장 좌석을 구분한다. |

개발가이드 1~2쪽에 따라 날짜는 `YYYYMMDD`, 조회 범위는 31일 이내, 페이지당 최대 100건으로 설정한다. 공통코드 4쪽의 `signgucode=11`을 서울특별시로 사용한다. 현재 공연 상태·현재 흥행순위·사후 관객수를 과거 예측 입력으로 사용하지 않는다.

목록 성공 응답으로 키 작동을 확인한다. 수집 도중 HTTP 400의 `Request Blocked`를 확인해 자동 재시도를 멈춘다. 성공한 41페이지에서 공연 ID 3,273개를 복구한다. 상반기 전체 수집 완료 자료로 부르지 않는다. 상세·시설 좌표 수집과 KOPIS 특징 실험도 아직 완료하지 않는다. 차단 원인을 임의로 단정하지 않으며 `kopis_partial_audit.json`과 비밀정보를 제거한 오류 응답을 보존한다.

최초등록일이 입력 시각보다 늦은 행을 제외하고 최종수정일도 확인하는 방식으로 적격성을 판단한다. 이 필터만으로 당시 일정의 모든 변경 이력을 복원했다고 주장하지 않는다. 자유문장 공연시간은 해석 가능한 경우만 사용한다. 공연기간 내 매일 공연했다고 가정하거나 좌석 수를 실제 관객수로 바꾸지 않는다.

[공식 Open API 안내](https://kopis.or.kr/por/cs/openapi/openApiInfo.do?menuId=MNU_00077)를 함께 참고한다. 코드의 회당 400요청·응답 크기·대기 간격은 자체 상한으로 둔다. 명세에서 호출 제한이 보이지 않는다고 무제한 서비스로 해석하지 않는다.

## 서울 문화행사

[OA-23041](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-23041&srvType=A&infSeq=2)의 `aiViewCulture`로 인증 조회한다. 총 19,642건을 수집하고 2025년 상반기와 겹치는 1,944건을 확인한다. 공연·축제 유형, 서울 좌표, 등록일을 만족하는 728건을 예비 특징 후보로 추린다.

반경 500m·1,000m 안의 등록된 행사 기간 수를 날짜별 노출 대리값으로 구성한다. 등록일이 입력일보다 늦으면 제외한다. 정확한 공연 횟수나 방문 인원으로 해석하지 않는다. 현재 스냅샷의 과거 행사이므로 당시 공개 버전과 수정 이력을 입증하지 못한 보조 실험으로 구분한다.

## 추가 연결 후보

- [서울 문화공간 OA-15487](https://data.seoul.go.kr/dataList/OA-15487/S/1/datasetView.do)의 유형·위치·좌석을 검토한다. 과거 시점의 개관·폐관 여부를 확인한다.
- [전국문화축제표준데이터](https://www.data.go.kr/data/15013104/standard.do)의 일정·위치·기준일을 검토한다. 서울 인근과 당시 알려진 일정만 연결한다.
- [서울 대기환경 OA-1200](https://data.seoul.go.kr/dataList/OA-1200/A/1/datasetView.do)을 실시간 수집 후보로 검토한다. 현재 조회를 과거 시간별 이력 확보와 혼동하지 않는다.
- 지하철 월별 통계는 공개 지연을 지킨 과거 통근 성향으로 검토한다. 같은 시간의 사후 승하차를 실시간 입력으로 사용하지 않는다.
- AWS 강수와 발표 시각이 보존된 기상 예보는 추가 키·역사자료 범위를 확인한다. 현재 두 키가 기상청·공공데이터포털 전체 서비스를 허용한다고 가정하지 않는다.

현재 기준 모델과 달력·전년도·문화행사 예비 비교는 추가 키 발급 없이 진행한다. 자료가 실제 오류를 줄이는지는 같은 모델에 하나씩 추가한 비교로 판단한다.

## 실시간 조건 추가 후 확인한 최신 상태

문화행사 과거 스냅샷과 미검증 ASOS 입력은 현재 주 학습 큐에서 제외한다. 서울 대기질은 OA-2221에서 2025년 이력을 확보하고, OA-1200의 현재 서비스 `ListAirQualityByDistrictService`로 25개 구 응답을 확인한다. 과거·현재 단위 대응과 약 60분의 관측→수신 차이를 기록한다. 점검중인 3개 구의 수치는 결측으로 처리한다. 2·3시간 전 입력과 수신 시각 검사를 구현하며 역사 수신 이력 미상은 보존한다.

Open-Meteo GFS의 이전 날 예보는 현재 미래 시각 수신 경로와 공식 모델 가용 메타데이터를 확인한다. 현행 이용 조건에서 키 없이 작은 연구 비교에 사용할 수 있다. 역사 실행 공개 시점은 입증하지 못해 조건부 예보 추가 실험으로 구분한다. 최종 근거·필드·원본·검수는 `추가데이터_병렬조사/보고서와재개방법.md`와 `GFS_실시간적격성_최종검토.md`에서 확인한다. 현재 비교를 진행하기 위한 추가 키는 요구하지 않는다.
