# 교통·이동 흐름 공공데이터 조사

확인일: 2026-10-20 KST. 연구 대상은 서울 고정 2,729개 따릉이 대여소의 입력 t에서 정확히 t+1시간 뒤 관측 수량 0대 여부다. 교통량·승하차·대여건수를 정답으로 바꾸지 않는다. 모델 학습, 기존 실험 큐 변경, 대용량 수집, 유료 신청은 수행하지 않았다. 서울 개인 API 키도 읽지 않고 공개 `sample` 키만 사용했다. 2025년 3·4분기 따릉이 정답·성과는 열지 않았다. 공식 포털의 연간 파일 **목록 메타데이터**에는 하반기 파일명이 함께 나오지만 하반기 원자료를 읽지 않았다.

## 결론과 적용 순서

데이터를 바로 모델에 붙였다는 의미의 ‘즉시’ 후보는 없다. 현재 확보 경로를 확인한 원천 중에는 **공개된 이전 기간의 버스·따릉이 시간대 프로필**, **따릉이 선행 OD**, **시간별 도로 교통량·속도**가 우선이다. 성능이 좋아진다는 직접 증거는 아직 없으며, 아래 영향 설명은 별도 표시한 경우를 제외하고 연구 가설이다. 우선순위는 확보 난이도와 예측 시점 준수 가능성을 평가한 것이지 실험 점수 순위가 아니다.

| 우선 원천 | 지금 할 수 있는 작업 | 남은 핵심 조건 |
| --- | --- | --- |
| TR07 버스 월간 시간대 승하차 | 기존 서울 일반키 또는 공개 월 CSV로 지연 프로필 구성 준비 | 공개일 뒤에만 갱신, 정류소 위치·ID 이력 검수 |
| TR16 따릉이 과거 시간대 이용 | 2024 선행 파일로 대여소별 시간대 출발 성향 구성 | 파일이 수백 MB라 현재 학습 중에는 처리하지 않음. 반기 공개 지연 준수 |
| TR15 따릉이 대여·반납 OD | 현재 API로 2025H1 작은 응답 수신 성공, 선행 OD 설계 가능 | 2024 당시 공개판·공개일 확인, 완료 반납과 수신 시각 제한 |
| TR01 교통량 | 2025H1 월 XLSX 6개 존재와 과거·현재 API 소표본 확인 | HH 구간 시작/종료 의미, 최초 게시 지연, 과거 수신 이력 미상 |
| TR02 도로 속도 | 2025H1 월 XLSX 6개, 현재 API 및 TData 1시간 응답 구조 확인 | 현행 API 관측시각 부재, 과거 확정본과 당시 제공본 차이 |

TR06 지하철 월별 시간대 승하차는 기존 `API와추가데이터.md`에 있던 후보의 구체화다. 새로운 원천으로 다시 세지 않는다. 대여·반납 OD, 따릉이 시간대 집계, 월별 이용건수도 동일 이용로그 계열이므로 서로 독립적인 세 신호를 확보했다고 주장하지 않는다.

최종 24행 목록의 분류는 추가작업 6, 조건부 14, 부적합 4다. `추가작업`은 공개 경로가 있으나 수집·연결·시점 검수가 더 필요하다는 뜻이다. `조건부`는 역사 공개본·시각·권한·이용조건 중 핵심 미확인 항목이 남았다는 뜻이다. `부적합`은 이번 2025H1 station×hour 입력으로 쓰지 않는다는 뜻이며 자료 자체의 일반적 가치에 대한 평가가 아니다.

## 상위 원천의 근거와 결합 설계

### 1. 버스 월간 시간대 승하차: 공개된 통근 성향

[OA-12913](https://data.seoul.go.kr/dataList/OA-12913/S/1/datasetView.do)은 서울시내·광역·마을버스의 월×노선×정류소별 시간대 승하차 **월 합계**다. 공식 설명은 전월 자료를 매월 5일 갱신한다고 하며, 2025년 1~6월 파일 목록의 수정일은 각각 2/6·3/6·4/6·5/6·6/6·7/6이다. 현재 메타데이터 수정일이 최초 대외 공개의 완전한 이력을 보증하지는 않지만, 당월에 쓸 수 없는 사후 집계라는 점은 분명하다.

`STOPS_ID`, `STOPS_ARS_NO`, `RTE_NO`를 문자열로 보존하고 정류소 위치를 연결한다. 대여소 반경 300/500m의 정류소별 이전 공개월 승하차 합계와 해당 시각 비중을 만든다. 노선 중복을 제거한 뒤 합산하며 24시간 월 합계를 당일의 실제 관측으로 해석하지 않는다. 예를 들어 2025-01-01 입력에 아직 공개되지 않은 2024-12 통계를 쓰지 않는다. 공개일의 정확한 시분이 없으면 수정일 다음날부터 반영하는 보수 정책을 명시한다.

가설은 ‘버스 이용이 집중되는 출발·도착 지역의 과거 패턴이 역세권 밖의 따릉이 연계 수요를 설명한다’이다. 동시간 실제 승객을 알게 된다는 뜻이 아니다. 서울 일반 API 키 외 추가 발급은 필요하지 않으며, 키 없는 CSV 경로도 있다. 시간대 컬럼 이름은 일부 시간에 `TNOPE`, 일부에 `NOPE`가 혼재하므로 응답 명세 그대로 읽어야 한다.

### 2. 따릉이 선행 시간대 프로필·OD

[OA-15245 시간대 이용](https://data.seoul.go.kr/dataList/OA-15245/F/1/datasetView.do)의 2024년 1~6월 월파일 수정일은 2024-07-30, 7~12월은 2025-01-16이다. 2025H1 파일은 2025-11-07로 표시된다. 파일명이 월별이어도 실시간·매월 즉시 공개 자료는 아니다. 따라서 2024H1을 2025H1 시작 전 공개된 선행 프로필로 검토하고, 2024H2는 2025-01-16 이후에만 추가한다. 각 파일은 수백 MB여서 이번 작업에서 내려받거나 집계하지 않았다.

공식 시간대 API는 대여일자·대여시간·대여소·이용자 집단별 `USE_CNT`를 제공한다. 총 건수만 집계하면 되고 성별·연령 특징은 이 과제에 필요하지 않다. **반납대여소가 없어 도착 흐름이나 OD 그래프를 직접 만들 수는 없다.** 반납 후에 계산되는 이동시간·거리도 진행 중인 대여의 t 시점 입력으로 쓰지 않는다.

[OA-15182 원천이력](https://data.seoul.go.kr/dataList/OA-15182/F/1/datasetView.do)은 대여·반납 시각과 양쪽 대여소를 제공한다. [명세](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-15182&srvType=A&infSeq=1)의 `RENT_DT`, `RTN_DT`, `RENT_ID/RTN_ID`, `RENT_STATION_ID/RETURN_STATION_ID`, `USE_MIN`으로 완료된 이동의 OD 비율과 여행시간 분포를 만들 수 있다. 대여·반납은 재고 변화의 직접 구성요소지만, 운영자 재배치·정비·불능 자전거를 모두 설명하지는 않는다.

각 입력 t에서 `RTN_DT≤t` **그리고** `published_at/received_at≤t`인 완료건만 허용한다. 대여가 t 이전에 시작됐더라도 t 이후 실제 목적지·반납시각을 알게 되는 건은 입력에서 제외한다. 이력으로 학습한 선행 OD에서 예상 도착을 계산하는 것은 검토 가능하지만 실제 미래 반납을 넣는 것과 구별한다. 고정 2,729개 대여소와 두 종류의 대여소 ID를 연결하고 신규·폐지·이전 대여소는 따로 처리한다.

현재 2024/2025 연간 ZIP은 둘 다 수정일 2026-04-22로 표시된다. 이 현재 ZIP만으로 2024말 공개판을 입증하지 못한다. 2025-01-01 5행이 지금 API에서 성공한 사실도 2025 당시의 수신 이력을 대체하지 않는다. 선행 공개판을 확보하기 전에는 `archived_reception_unknown` 조건부 비교로 남긴다. 전체 연간 ZIP은 약 1.7~2GB여서 이번 작업에서 수집하지 않았다.

마지막 누락 점검에서 더 실용적인 **공개 집계 대체 경로**를 확인했다. [OA-21229 따릉이 대여소별 대여/반납 승객수](https://data.seoul.go.kr/dataList/OA-21229/F/1/datasetView.do)는 1일 5분 단위 대여소 출발지·도착지 집계이고 **매일 5일 전 자료를 적재**한다. 2024년 월 ZIP들과 2025H1 6개 월 ZIP이 현재 목록에 남아 있다. 2025년1월은45.42MB·2/8수정, 2월61.1MB·3/8, 3월108.02MB·4/8, 4월138.44MB·5/8, 5월145.9MB·6/8, 6월146.1MB·7/8이다. 파일은 수집하지 않았다.

따라서 전체 원천 연간 ZIP보다 **2024 선행월 집계로 OD 그래프를 만드는 경로를 먼저** 검토할 수 있다. 2024-12 월판은2025-01-08, 2024-11은2024-12-08로 표시되므로 2025-01-01에는11월까지 공개된 판부터 검토한다. 현재 일별 원본의 D-5 적재 정책이 2025 매일의 최초 게시 시각까지 입증한 것은 아니다. 5분은 측정/집계 빈도이고 실시간 제공 빈도가 아니다. `집계_기준`과 출발/도착 집계 정의, 대여소 마스터 ID와 시간구간 의미를 추가 검수해야 한다. 이 경로는 같은 따릉이 OD 가족이므로 TR15에 묶었다.

[OA-15249 월별 대여소 이용건수](https://data.seoul.go.kr/dataList/OA-15249/A/1/datasetView.do)는 더 작은 대체 경로다. 2024H1 파일은 0.77MB·2024-07-12, H2는 0.78MB·2025-02-20로 표시된다. 시간대·반납·OD가 없는 만큼 기본 수요 규모 특징에 한정하고, 같은 원천의 집계를 독립 데이터로 중복 계산하지 않는다.

### 3. 교통량: 과거 원본과 현재 경로를 함께 확인

[TOPIS 교통량 안내](https://topis.seoul.go.kr/refRoom/openRefRoom_2.do)는 24시간 검지·시간/일 단위 통계 생성, 현재 139지점(도심24·시계38·교량21·간선46·도시고속10)을 설명한다. 지점별 일자별 자료는 익월 말 제공으로 안내한다. API의 HH가 구간 시작인지 종료인지, 어느 시점에 완성·공개되는지의 명확한 보장은 찾지 못했다.

공식 웹페이지가 쓰는 공개 목록 요청을 확인해 2025H1 월 XLSX 6개가 존재함을 검증했다. 게시물 생성·수정 시각이 함께 있으며 다음처럼 H1 파일의 두 시각은 같았다. 서버 시간대의 별도 표기는 없으므로 이를 KST 정밀 발표 시각으로 단정하지 않는다.

목록 원문은 `공식문서/topis_volume_2025_month_files.json`에 보존했다. GET이 JSON을 반환하지 않아 공식 `common.js`의 POST 방식으로 교정했으며 인증·차단을 우회하지 않았다. 파일 자체는 아직 다운로드하지 않았다. 월파일에 일자×시간대 원자료가 어떤 시트·단위로 들어있는지는 다음 소표본 검수 과제다. 목록만 보고 완전한 station×hour 특징이 준비됐다고 하지 않는다.

VolInfo는 지점·일자·시간을 지정해야 한다. 현재 안내 지점 139개를 2025H1의 4,344시간마다 요청한다고 가정하면 약 **603,816회**이며 차로 페이징이 더 필요할 수도 있다. 실제 2025 운영 지점 수·전체 수집 비용을 측정한 값은 아니다. 전체 API 수집을 진행하지 않고 월파일을 먼저 검토한다.

`SpotInfo`의 TM 좌표를 정확히 변환한 뒤 대여소 주변 500/1000m 또는 근접 3지점의 방향별 교통량을 연결한다. 대여소별 관측소까지 거리를 함께 보존하고 멀리 있는 값을 같은 동네 실측값으로 부르지 않는다. 가설은 자동차 이동량과 통근·혼잡의 공통 흐름이 따릉이 수요를 설명할 수 있다는 것이다. 자동차 교통량을 자전거 통행량으로 바꾸지 않는다.

입력은 t 이전에 종료·공개·수신된 구간만 사용한다. HH 의미·지연을 확인하기 전 lag2/3h는 검토 정책일 뿐 적격성의 보장이 아니다. 과거 월 확정본에 단순 시차를 주는 것만으로 당시 공개값을 재현했다고 주장하지 않는다.

### 4. 도로 속도: 월 원본과 실시간 뷰를 한 원천으로 묶기

[TOPIS 속도 안내](https://topis.seoul.go.kr/refRoom/openRefRoom_1.do)는 일반도로 택시 GPS의 5분 속도와 5분·15분·30분·1시간 통계 생성을 설명한다. 현재 범위는 510도로다. 도로별 일자별 통행속도 파일은 익월 10일, 월간 보고서는 익월 말 제공으로 구분한다.

2025H1 **도로별 일자별 속도 XLSX** 6개의 목록 생성일은 2/4·3/4·4/11·5/7·6/4·7/4다. 별도의 월간 PDF 보고서와 혼동하지 않았다. `공식문서/topis_speed_2025_daily_data_monthfiles.json`에 경로·시각을 보존했다. 일부 월간 PDF는 생성일보다 수정일이 늦어 현재본을 최초 공개본으로 취급하면 안 된다는 사례도 확인했다.

[TrafficInfo 공식 명세](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-13291&srvType=A&infSeq=1)는 링크 ID·속도·여행시간을 반환하지만 관측시각이 없다. [TData 1015 1시간 소통정보](https://t-data.seoul.go.kr/dataprovide/trafficdataviewopenapi.do?data_id=1015)는 기준일·시간코드·`timeNm`·링크·평균속도를 반환한다. `~18시`라는 예시가 있어도 해당 명세의 종료시각 의미를 다른 VolInfo 서비스로 옮겨 추정하지 않는다. TData 문서 표와 JSON 예시의 일부 필드 이름도 달라 실제 응답 검수가 필요하다.

TrafficInfo는 서울 일반키 경로다. TData는 별도의 인증키·활용신청이 필요하며 [이용안내](https://t-data.seoul.go.kr/userguide/guideopenapi.do)는 하루 1,000회 제한을 명시한다. 기존 서울키와 호환된다고 가정하지 않는다. 월파일은 추가키 없이 검토할 수 있어 우선 경로다. 주차·택시·버스에 속도 원천이 재인용돼도 같은 TOPIS 링크 속도를 새로운 독립 후보로 다시 세지 않는다.

### 5. 지하철 월별·혼잡 통계의 정확한 위치

[OA-12252](https://data.seoul.go.kr/dataList/OA-12252/S/1/datasetView.do)는 월×역×호선의 24개 시간대 합계다. 기존 조사와 중복이므로 신규 원천 수에는 포함시키지 않는다. 작업일 `JOB_YMD`는 발표 시각과 다르다. 역 좌표와 연결해 이전에 공개된 월의 해당 시각 비중을 사용하고, 당월 실제 승하차를 입력하지 않는다. 현재 새 [서울교통공사 역별승하차 API](https://www.data.go.kr/data/15143845/openapi.do)는 2025-06-10 등록·최근 일주일만 제공한다고 설명하므로 이 서비스 존재를 2025H1 전체 역사자료 확보 증거로 쓰지 않는다.

[1~8호선 혼잡도 OA-12928](https://data.seoul.go.kr/dataList/OA-12928/F/1/datasetView.do)는 요일구분·역·방향·30분 단위의 조사 평균이며 실시간 혼잡이 아니다. 2024H1 파일은 수정일 2024-09-05, 2024말 판은 2025-03-31, 2025Q1 판은 2025-04-28로 표시된다. 최신 2025H1 혼잡도를 상반기 전체 입력에 소급하지 않는다. 이 서울 페이지는 공공누리 **3유형(출처표시+변경금지)**를 표시하므로 가공 특징 이용범위를 먼저 확인한다.

[9호선 OA-22197](https://data.seoul.go.kr/dataList/OA-22197/F/1/datasetView.do)는 다른 운영범위의 30분 조사 평균이다. 2023 자료의 수정일 2024-11-12는 선행 공개판 후보 근거가 있지만 2024·2025 자료는 현재 수정일이 2026-03-30이다. 2024판이 2025초에 사용 가능했다고 단정하지 않는다.

## 정비·재배치의 공개 범위

공개 고장신고는 확인했지만 수리완료·회수·배송·대여소간 운영자 재배치 원천로그의 공개 API/파일은 이번 공식 검색에서 찾지 못했다. ‘존재하지 않는다’거나 ‘오직 운영자 전용이다’라고 단정하지 않는다. 담당기관 추가제공 문의가 필요한 미확인 자료다. [서울시 공식 2024 재배치 사업 설명](https://mediahub.seoul.go.kr/archives/2011165)은 재배치 활동이 운영되고 있음을 보여줄 뿐 공개 station×hour 이력을 제공하지 않는다.

연속된 대여 기록 사이 자전거 위치가 달라졌다는 사실만으로 확정 재배치를 만들지 않는다. 누락 대여·ID 변경·정비 등 다른 이유가 가능하며, 미래 대여를 이용해 t 이전 재배치를 알아낸다면 시점 누출까지 생긴다. 필요하면 사후 잔차 설명용 추정값과 운영 시 입력을 구분해 별도 연구한다.

## 공통 연결·시점 규칙

1. 각 행에 `event_or_observation_time`, `interval_end`, `published_at`, `provider_generated_at`, `received_at`, `valid_from/to`, `source_version`의 존재 여부를 구분한다. 없는 시각을 다른 시각으로 복사하지 않는다.
2. 관측 입력은 완료구간이 t 이전이고 실제 수신도 t 이전일 때만 채택한다. 예보/예정통제는 미래 유효시각이어도 t 이전 알려진 계획판만 허용한다. 과거 확정본에는 수신미상 태그를 유지한다.
3. 월·반기·연간 집계는 공개일 뒤부터 쓰는 이전기간 프로필이다. 당월/당분기 평균을 같은 기간으로 소급하지 않고, 휴일/요일도 해당 통계가 실제 제공하는 구분까지만 사용한다.
4. 고정 대여소 ID·좌표·설치/이전 시점과 정류소·역·링크의 변경 이력을 검수한다. 반경·가중치·lag는 사전에 좁은 후보로 정하고 2025H1 개발 안에서만 비교한다. 여기서는 어떤 값도 성능 최적화하지 않았다.
5. 결측/장애·관측소 원거리·호출 실패와 실제 0을 구별한다. 다음 시간대 건수·사후 해제/수리/실제반납은 과거 입력으로 넘기지 않는다. 수량 0은 대여수요 0이나 이용불가 상태와 같지 않다.

## 저장·검수와 재개

- `후보목록.csv`: 공통 21열, 원천 24행. API와 같은 원천의 파일·집계를 묶고 중복 관계를 `evidence_level`에 기록했다.
- `출처검증.json`: 수신시각·URL·HTTP결과·소표본 필드·해시. HTTP200 문서와 실제 API INFO-000을 구분했다.
- `공식문서/`: 공식 명세·파일목록의 작은 텍스트/JSON, 공개 웹페이지 소스 일부.
- `공개샘플/`: 5행 이하 응답 8개. 지하철/버스 월샘플은2024-12, 대여이력은2025-01-01, 교통량은2025-01-01 및현재1지점이며 현재주차/일별버스집계도 포함한다.

CSV 열수·24행 고유 ID·JSON 해석·원본 파일 존재를 확인한다. 모델 학습·특징 비교·대용량 정제 검사는 하지 않는다. 현재 학습 종료 뒤 자료를 실제 붙일 때 먼저 작은 월파일의 시간 의미·단위를 검수하고, 준비된 기존 기준모델에 원천을 하나씩 추가해 비교해야 한다.

담당기관 확인이 필요한 사항은 VolInfo HH의 구간 정의·평소/최대 게시 지연·정정이력, 월속도/교통량 원본의 당시 공개판, 따릉이 OD의 2024 공개판 및 현 API 게시 지연, 고장/재배치 로그의 공개범위다. 추가키는 선택적 TData·버스/ITS·지하철 전용 API에서만 필요하며 이번에 자동 발급·신청하지 않았다.
