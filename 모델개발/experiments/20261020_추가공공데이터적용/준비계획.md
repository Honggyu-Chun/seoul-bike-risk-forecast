# 추가 공공데이터를 모델 입력으로 준비하는 기준

작성일은 2026-10-20이다. 기존 v4의 A/B/C 개발 결과 일부를 이미 확인한 뒤 작성한 후속 준비 계획으로 구분한다. v4의 고정 실험과 기존 성과를 덮어쓰지 않는다. 새 자료 준비와 현재 진행 중인 모델 학습을 구분하며 학습은 한 번에 하나만 실행한다.

## 먼저 확보·검수하는 자료

버스정류소 위치의 정적 특징 4개는 별도 조사에서 2,729개 대여소에 연결하고 독립 거리 검사를 통과한다. 이 정제본의 해시와 시점 제한을 유지한다. 버스 노선·배차·승객 수를 확보한 것으로 바꾸어 설명하지 않는다.

따릉이 대여·반납 흐름은 [서울시 OA-21229](https://data.seoul.go.kr/dataList/OA-21229/F/1/datasetView.do)의 **2024년 11월 집계판 한 개**부터 확인한다. 공식 목록의 수정일은 2024-12-08로, 현재 개발 대상인 2025년보다 앞선다. 현재 표시되는 수정일만으로 당시 최초 공개·수신·원본 불변을 인증하지 않는다. 원천은 매일 5일 전 자료를 적재한다고 설명하므로 5분 집계를 실시간 관측으로 해석하지 않는다.

## 헤더 확인 뒤 고정하는 준비 규칙

실제 첫날 파일의 CP949 헤더는 날짜·집계 기준·5분 시간대·출발/도착 ST-ID·명칭·건수·이용분·거리로 구성한다. 명칭은 시민용 대여소 번호가 아닌 행정동 코드 형태이므로 이름 유사도 연결을 사용하지 않는다. 다음 규칙은 전체 원천 집계나 모델 학습 전에 고정한다.

- `출발시간`과 `도착시간`은 같은 이동의 다른 시간 기준일 수 있으므로 합쳐 이동 총건수로 세지 않는다. 전자는 출발지, 후자는 도착지의 시간대 프로필로 각각 집계한다. 실제 기준값 종류를 전 날짜에서 확인하고 예상 밖 값은 중단 조건으로 삼는다.
- 날짜는 파일명과 일치하는지 확인하고 시간대는 00:00~23:55의 5분 격자인지 검사한다. 건수는 유효한 음이 아닌 정수로 확인한다. 동일 날짜·기준·시간대·출발·도착 키의 중복을 확인하며 중복이 있으면 먼저 원인을 검토한다.
- ST-ID·요일·시간별로 수록 건수의 합과 **실제 행이 나타난 날짜 수**를 각각 저장한다. 관측된 날짜당 평균과 수록 일수 비율을 구분한다. 파일에 행이 없는 대여소·시간을 실제 이용 0이라고 확정하지 않는다. 수록되지 않은 셀은 모델 입력에서 결측으로 유지한다.
- 달력상의 요일별 날짜 수는 2024-11의 30개 일파일 존재를 검사한 뒤 노출 분모로만 기록한다. 원천이 모든 실제 이동을 빠짐없이 수록했다는 인증으로 사용하지 않는다.
- 이동 관계는 출발 기준의 월 집계만 사용해 출발 ST-ID→도착 ST-ID별 합계를 구성한다. 도착 기준을 더해 이중 집계하지 않는다. 실제 미래 반납은 사용하지 않는다. 그래프 학습과 가중 이웃 특징의 구체적인 구조는 후속 비교 전에 추가 고정한다.
- 기존에 받은 현재 bikeList의 고유 ST-ID↔대여소 번호 연결을 잠정 교차표로만 사용한다. 2024 코호트와 현재 번호가 일치하고, 공백·유니코드만 정규화한 이름이 같고, 좌표 차이가 50m 이내인 연결을 보수적 후보로 표시한다. 50m는 프로젝트의 오연결 억제 기준이며 논문이 보장한 허용 오차가 아니다.
- 현재 교차표로 과거 동일성을 인증하지 않는다. 과거 마스터 미확보 표시와 미연결·이름 변경·위치 차이를 모두 저장한다. 고정 2,729개 대여소를 줄여 성능을 유리하게 만들지 않는다. 연결하지 못한 곳은 별도 결측 마스크를 둔다.
- 전체 입력 준비는 2024 흐름과 정적 메타데이터만 읽는다. 2025년 정답·성능으로 연결 규칙을 고르지 않으며 3·4분기 미개봉 시험은 열지 않는다.

### 실제 원천에서 발견한 예외를 처리한다

첫 전수 읽기에서 11월 27일 CSV만 UTF-8이고 다른 확인 날짜는 CP949임을 발견한다. 이 파일은 199바이트의 헤더뿐이며 실제 데이터 행이 없다. 문자 오류를 무시하거나 가짜 행을 만들지 않고, 각 구성원의 헤더를 엄격히 해독해 예상한 열 목록과 정확히 맞는 UTF-8/CP949만 허용한다.

헤더만 있는 날짜는 전체 자료 누락으로 기록한다. 그 날의 실제 대여·반납이 0이었다고 확정하지 않는다. 프로필의 수록 일수 비율은 같은 요일의 **비어 있지 않은 일파일 수**를 분모로 사용하고, 달력 일수와 그에 대한 비율도 진단 열로 따로 보존한다. 행이 있는 파일도 모든 실제 이동을 완전히 수록했다는 보장은 남아 있지 않으므로 관측된 날짜당 평균만 입력 후보로 남긴다. 이 수정은 2024 원천의 형식·누락 검수에 따른 것으로 2025 성능을 보고 고른 규칙이 아니다.

## 후속 비교 전에 고정할 항목

원천 헤더와 집계 기준을 확인한 뒤 특징 정의, 날짜 정규화의 분모, ID 연결 규칙, 누락 처리, 허용 시점, 원천·정제본 해시를 기록한다. 준비가 끝난 경우에만 같은 기본 모델에 원천을 한 군씩 추가하는 후속 비교 계획을 작성한다. 이미 성과를 본 개발 기간의 추가 탐색이라는 점을 표시하고 2025년 3·4분기 정답은 열지 않는다. 비교 결과가 없으면 성능 향상을 주장하지 않는다.
