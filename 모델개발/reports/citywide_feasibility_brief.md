# 서울 전역 따릉이 수요 예측: 간단한 데이터·평가 검토

확인일: 2026-10-19. 현재 목표는 **공연 정보 없이 서울 대여소별 시간대별 대여 건수를 더 정확하게 예측하는 서비스의 가능성과 구조를 정하는 것**이다. 이번 후속 검토에서는 새 모델을 학습하거나 웹앱을 구현하지 않았다.

**판단: 데이터 관점에서 진행 가능하다.** 실제 따릉이 정답 자료, 대여소 위치, 같은 기간의 기상청 관측 원본이 확보됐다. 정확도가 개선되는지는 이후 공정한 비교 실험으로 확인해야 한다. 무기록 시간의 0건 판정과 실제 서비스에 들어오는 입력의 지연은 설계에서 해결할 조건이다.

서울시 위 자료는 제공 페이지의 공공누리 1유형을 확인했다. 공원 사진·연결 웹사이트 저작물까지 같은 조건이라고 확대 해석하지 않고, 우선 위치·이름 등의 필요한 속성만 사용한다. 기상청 API의 제공 안내는 공공저작물 출처표시 제1유형이다.

원본 메타데이터·해시는 [다운로드 기록](citywide_download_manifest.json), 기상 시간 연결은 [검증 JSON](citywide_weather_verification.json), 전역 공간 연결은 [검증 JSON](citywide_spatial_feasibility.json)에 있다. 지하철 일별 CSV는 각 행에 빈 마지막 필드가 하나 더 있었고, 이를 확인한 뒤 정리했다. 단순히 pandas로 열면 날짜가 인덱스로 밀리는 문제가 있었다.

## 2. 휴일 자료와 접근이 안 된 경로

- [한국천문연구원 특일정보 API](https://www.data.go.kr/data/15012690/openapi.do): 공식 문서에서 `공휴일 정보 조회`, `locdate, dateName, isHoliday`, 연도 필수·월 선택, 무료·자동승인·개발계정 10,000건 안내를 확인했다. 키 없이 실제 호출한 응답은 HTTP 400/오류 10이었고, 유효한 공식 공휴일 목록은 받지 못했다. 환경 설정과 관련 변수 이름에서도 사용할 인증 바인딩이 없었다. 인증키 값을 채팅으로 요청하지 않는다.
- [한국천문연구원 2025년 달력자료](https://astro.kasi.re.kr/life/post/calendarData?search_year=2025): 초기 접근 거절 뒤 재조회에 성공해 실제 표를 읽었다. 자료 생성은 2024-05-07이며, 페이지 자체가 공식 발표 자료가 아니라고 명시한다. 표에는 2025-01-27 및 2025-06-03이 공휴일로 기재되어 있지 않다. 이후 지정된 날짜까지 반영한 최신 공식 목록으로 바로 취급하면 안 된다.
- `python-holidays` 0.106도 별도로 확인했다. 2025년 19개 휴일 날짜가 생성되며 위 두 날짜가 포함된다. **오픈소스로 계산된 파생 달력**이며 공식 API 원응답으로 표시하지 않았다. 임시공휴일을 포함한 공식 목록과 최종 대조하는 것이 좋다.
- 미국 NOAA·NASA의 공식 기상 경로도 검토했지만 최초 요청들은 이 환경의 프록시 CONNECT 403으로 원본에 도달하지 못했다. 이것은 데이터가 없다는 증거가 아니다. 국내 기상청 원본을 실제로 확보했으므로 해당 대체 자료를 별도로 받아올 필요는 없다. UCI는 초기 거절 뒤 다운로드에 성공했다.

**사용자에게 보완을 부탁할 자료는 공식 2025년 공휴일 목록 하나다.** 핵심 따릉이·위치·날씨·지하철·공원은 다시 받아주실 필요가 없다.

1. [한국천문연구원_특일 정보](https://www.data.go.kr/data/15012690/openapi.do)에 접속해 필요한 경우 활용신청을 한다.
2. 기능은 **공휴일 정보 조회**를 선택한다. 기념일·국경일 정보 조회와 구분한다.
3. `solYear=2025`, `numOfRows=100`, `pageNo=1`, `solMonth`는 비워서 연간 결과를 조회한다. 공식 문서에서 월은 선택항목이다.
4. 응답 본문을 XML 또는 JSON 파일로 저장해 올려주면 된다. CSV로 내보낼 수 있다면 `locdate, dateName, isHoliday`를 포함하면 된다. 인증키나 키가 들어간 요청 URL 대신 **결과 파일만** 전달한다.

웹에서 조회가 어려우면 2025년 공식 공휴일·임시공휴일을 포함한 최신 목록을 받아도 된다. 연초 월력요항 PDF만으로는 이후 추가된 임시공휴일을 보완하지 못할 수 있다. 이 보완은 서비스 기획과 다른 자료의 검토를 중단시킬 조건은 아니다.

## 3. 서비스는 이렇게 구상하면 된다

**“서울 대여소별 시간대별 이용량 예측 및 운영 지원 대시보드”**를 권한다. 사용자는 운영 담당자이며, 서울 지도에서 날짜·시간·대여소를 선택해 예상 대여 건수와 수요가 많은 대여소 목록을 본다. 과거 날짜에서는 실제값·기본 모델·개선 모델의 그래프와 오차도 함께 볼 수 있게 한다.

흐름은 `공개 파일 수집 → 대여소×시간 정답과 과거 패턴 생성 → 모델 학습 → 시간대별 예측을 미리 계산 → 지도·그래프로 제공`이다. Python/LightGBM, 작은 API, Streamlit 등의 화면으로 시작할 수 있다. 서울 전역 예측을 서버에서 일괄 계산해 저장하면 사용자가 볼 때마다 전체 모델을 다시 돌릴 필요가 없다.

정확도 개선은 다음과 같이 시험할 수 있다. 모든 구성을 지금 구현할 필요는 없다.

| 비교 단계 | 구성과 역할 |
|---|---|
| B0 단순 기준 | 같은 대여소의 사용 가능한 과거 동일 요일·시간 평균 또는 전주 값. 사용 가능 시점은 평가 가정에 맞춘다 |
| B1 주 기준 | LightGBM + 해당 대여소의 과거 패턴 + 시간/요일/휴일 + 예측 시점에 사용 가능한 기상 |
| M1 개선 후보 | **같은 LightGBM**에 주변 대여소의 과거 패턴·거리, 이용 패턴이 비슷한 대여소 그룹의 특성 등을 추가 |

주변 대여소의 **현재 1시간 이용량**이 아니라, 공개된 과거 자료에서 계산할 수 있는 패턴부터 검토한다. 같은 대여소의 미래 정답이나 시험기간 전체로 만든 평균을 특징에 섞지 않는다. 군집·평균·대체 규칙도 학습기간 안에서 만든다. 주변 정보가 실제로 도움이 되는지는 B1/M1의 동일 시간순 시험으로 확인한다. 날씨·휴일은 합리적인 기본 입력이므로 그것을 넣었다는 사실만으로 새로운 방법이라고 주장하지 않는다.

현재 공개 대여이력은 반기 갱신이라 현재 시점의 직전 1시간 대여량을 받는 경로가 아니다. 따라서 최초 제품은 **공개 과거 자료를 이용한 시간대별 이용량 전망과 과거 재생·검증**으로 정하는 것이 현실적이다. 실시간 변화 반영을 약속하려면 최근 대여 로그 공급 경로를 따로 확보해야 한다. 현재 재고를 대여 건수로 대신할 수 없다.

날씨도 같은 주의가 필요하다. 받은 파일은 사후 연간 관측 자료이며 과거 순간의 공개 버전이 아니다. 미래 시간의 실제 관측 날씨를 예측 입력에 넣으면 안 된다. 처음에는 이용 가능 시점에 맞게 지연한 관측 또는 사용 가능한 날씨 없이 평가할 수 있다. 실제 예보를 넣는 확장은 [기상청 단기예보 API](https://www.data.go.kr/data/15084084/openapi.do)의 공식 서비스와 요청 항목을 확인했지만, 인증 호출·과거 발행 예보 확보는 아직 검증하지 않았다.

## 4. 과제 평가 요소를 만족시키는 방법

첨부 평가 안내 2~3쪽 기준 사전평가 40%, 최종평가 60%다. 새로운 딥러닝 알고리즘을 반드시 만들라는 조건은 확인되지 않았다.

| 평가 요소 | 이 프로젝트에서 준비할 증거 |
|---|---|
| 사전: 주제 적합성·문제 정의 | 실제 서울 대여소의 성사된 대여 건수 예측. AI 예측이 서비스의 중심 기능이며 정답 자료가 있음 |
| 사전: 창의성·차별성 | 일반적인 주제라는 약점은 인정해야 함. 주변·유사 대여소 패턴이 언제 어디에서 오차를 줄이는지라는 구체적인 비교 질문과 운영 화면으로 보완. 개선은 아직 가설 |
| 사전: 계획서·발표·질의응답 | 실제 파일·컬럼·건수·연결 결과, 미확인 사항, 시간순 분할과 4명 산출물·일정을 제시. 확보하지 않은 자료·성능을 완료로 적지 않음 |
| 최종: 모델 성능·Baseline 대비 우수성 | B0/B1/M1의 같은 정답·시험행·기간, B1/M1의 같은 모델·튜닝 예산. 주지표 MAE, 보조 RMSE. 전체·출퇴근/고수요 시간·대여소별 결과와 표본 수를 공개 |
| 최종: 구현 완성도·적용 가능성 | 지도 → 대여소 선택 → 예측/실제 그래프 → 모델 비교가 연결되는 작동 시연. 신설·폐쇄·자료 지연·결측을 화면에서 구분 |
| 최종: 문서화·오픈소스·발표·동료평가 | 출처·버전·집계/0건 처리 규칙·재현 명령·API 문서·GitHub/Wiki. 데이터 QA, 모델, API, 화면의 담당 산출물과 기여 기록 |

평가 전에 해결할 가장 큰 문제는 **기록 없음과 실제 0건의 구분**이다. 실제 대여가 있었던 시간만 골라 성능을 제시해서는 안 된다. 정답 마스크와 대여소 운영 상태, 누락·중복 처리 원칙을 먼저 확인하고, 0을 포함한 전체 운영시간을 공정하게 평가해야 한다. 이전 행사 아이디어에서 실행한 관측시간 103개 시험은 서울 전역 모델의 성능 증거가 아니다.

학기 프로젝트로는 구상이 가능하지만, 1월 한 달을 연중 성능으로 대표할 수 없다. 정식 비교 전에 계절을 포함하는 여러 달의 이용량·기상을 확보하고 최종 시험기간을 미리 고정해야 한다. “몇 % 좋아진다”는 목표·결론은 실제 첫 비교 후 정한다. 품절 감소·재배치 효과는 별도 실험 없이 주장하지 않는다.

## 5. 확인 기록과 재확보

이번에는 기존 대여 원본을 재사용하고 추가 파일 열기·시간/공간 연결만 수행했다. 모델 학습·성능 튜닝은 하지 않았다. 2025년 기상청 파일은 공식 파일 목록 조회와 사이트의 공개 샘플 다운로드 기능으로 확보했으며, 실제 내용은 연간 8,760시간이었다. 중첩 ZIP 두 단계의 CRC 검사도 통과했다.

추가 다운로드는 `data/citywide_downloads.json`에 저장했다. 공개 파일 재확보 예:

```bash
cd /workspace/P_Project
uv run --frozen --cache-dir /workspace/.cache/uv python scripts/fetch_public.py \
  --manifest data/citywide_downloads.json --raw-dir data/raw/citywide_review
```

KMA 파일 조회 조건은 `dataFormCd=F00502`(시간), `stnIds=108`(서울), 연도 2025였다. 공식 UI에서 다시 받을 경우 **기상자료개방포털 → 기상관측 → 지상 → 종관기상관측(ASOS) → 파일셋 → 시간·서울(108)·2025**로 찾을 수 있다. 현재 확보된 파일명은 `SURFACE_ASOS_108_HR_2025_2025_2026.zip`이다. 현재 이 파일을 사용자가 다시 받아줄 필요는 없다.
